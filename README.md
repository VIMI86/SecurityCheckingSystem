# SentinelAI

SentinelAI принимает событие информационной безопасности, разбирает его двумя агентами и сохраняет предложение по реагированию. Агент не выполняет действие сам. Отдельная политика отвечает `ALLOW`, `DENY` или `REQUIRE_APPROVAL`, а предложенная операция в этой версии только записывается и не запускается на хосте.

Событие можно отправить со страницы `http://127.0.0.1:8000/ui` или запросом `POST /tasks`. На странице видны шаги Analyst, Security и Policy, статус задачи и журнал решений.

## Зачем это нужно

Сообщения IDS, журналов и сервисов нужно быстро разобрать, но давать модели прямой доступ к инфраструктуре опасно. SentinelAI разделяет разбор, предложение действия и разрешение на него. Модель готовит черновик. Политика решает, можно ли это действие учитывать. Журнал хранит, кто что предложил и какое решение принято.

## Как проходит одна задача

1. Клиент передаёт тип события и исходные данные.
2. API записывает задачу в PostgreSQL и публикует сообщение в RabbitMQ.
3. Orchestrator забирает сообщение и вызывает Analyst Agent. Тот выделяет факты.
4. Security Agent по этим фактам предлагает действие: `record_only`, `block_host`, `isolate_host` или другое имя.
5. Policy Service сверяет имя с таблицей `policies`.
6. Результат агентов, решение политики и события аудита сохраняются. Статус задачи становится `done`.
7. Клиент открывает задачу по идентификатору. Повторное чтение в течение 30 секунд берётся из Redis.

Ни одно из трёх известных действий не исполняется. В записи политики поле выполнения остаётся выключенным.

## Решения политики

| Действие | Решение | Смысл |
| --- | --- | --- |
| `record_only` | `ALLOW` | Событие можно только зафиксировать |
| `block_host` | `REQUIRE_APPROVAL` | Блокировка узла ждёт отдельного подтверждения |
| `isolate_host` | `REQUIRE_APPROVAL` | Изоляция узла ждёт отдельного подтверждения |
| любое другое имя, в том числе пустое | `DENY` | Действие вне списка запрещено |

## Что делает каждый сервис

| Сервис | Роль |
| --- | --- |
| API | Принимает задачи, отдаёт страницу `/ui`, читает и меняет записи, кэширует статус |
| Orchestrator | Потребляет очередь, вызывает агентов, применяет политику, пишет аудит |
| Agent | Отвечает на `POST /analyze` в ролях Analyst и Security |
| PostgreSQL | Хранит задачи, результаты, политики и аудит |
| Redis | Кэш статуса задачи с TTL 30 секунд |
| RabbitMQ | Очередь `sentinel.tasks`. Три узла, очередь типа quorum |

Модель подключается через адаптер. `LLM_PROVIDER=mock` возвращает фиксированный разбор и не открывает сеть. `LLM_PROVIDER=ollama` вызывает Ollama по адресу из `.env`.

Задачу можно создать, прочитать, изменить и удалить. Изменение и завершение обработки сбрасывают кэш. Если публикация в очередь не удалась, задача переходит в `failed`.

## Запуск

```bash
cp .env.example .env
docker compose up --build -d
```

Страница: `http://127.0.0.1:8000/ui`.

Проверка, что API видит базу, кэш и брокер:

```bash
curl -fsS http://127.0.0.1:8000/ready
```

Пример задачи:

```bash
curl -fsS -X POST http://127.0.0.1:8000/tasks \
  -H 'content-type: application/json' \
  -d '{"event_type":"ids_alert","payload":{"src":"10.0.0.8","msg":"ET SCAN"}}'
```

Порты API, Orchestrator и Agent открыты только на `127.0.0.1`: `8000`, `8001` и `8002`. Панель RabbitMQ — `http://127.0.0.1:15672`. PostgreSQL и Redis наружу не публикуются. Пароль учебной базы и брокера по умолчанию `sentinel`. Файл `.env` в git не входит.

Остановка: `docker compose down`. Том PostgreSQL при этом сохраняется.

## Сеть и восстановление

Контейнеры разнесены по сетям `sentinelai_edge`, `sentinelai_app`, `sentinelai_data` и `sentinelai_broker`. Agent не подключён к сети базы и к сети брокера. Фильтр на хосте разрешает только рабочие соединения API и Orchestrator к PostgreSQL, Redis, RabbitMQ и вызов агента. Остальные новые соединения к портам базы, кэша и брокера отбрасываются.

```bash
./scripts/firewall.sh apply
./scripts/firewall.sh status
```

Для PostgreSQL есть standby и скрипты переключения, резервного копирования и восстановления. Для RabbitMQ остановка одного узла из трёх не останавливает quorum-очередь.

```bash
./scripts/postgres-failover.sh
./scripts/postgres-backup.sh
./scripts/rabbitmq-cluster.sh
```
